# Runtime 连续稳定性与资源验收

日期：2026-10-18；设备 M5 MacBook Air / 32 GB，交流电；基线提交 `560a9f4`。

## 当前验收口径

5–6 秒/步仅用于冷机、1024²、纯文生图、单 Turbo LoRA 基准。多 LoRA、参考图、复杂编辑按各自负载记录合理增量。优先级依次为系统响应、新增 Swap-out 与持续内存压力、权重/LoRA/KV/编译图/缓冲释放、连续生成稳定性，最后才是单步速度。

**性能有效性与资源安全独立判定：**

- 启动前 thermal nominal 且 BF16 探针连续两次达到冷机基线 13.1 TFLOPS 的 98%，间隔 30 秒。此项用于标记测试开始条件。
- 每张在 prefill 前、去噪 2/4/6 步后记录吞吐和热状态。低于 12.838 TFLOPS 只标记该段不能作冷机测速成绩；继续完成任务，不等待恢复，不由此取消。后续连续张之间不人为冷却。
- 本次压力测试独立的资源保护条件为：系统 critical 内存压力持续至少 15 秒，且该 critical 区间新增 swap-out 至少 128 MiB，才向 GenerationEngine 发出合作取消。这是本机压力实验的保守保护线，不是 macOS 通用限额，也不作为新增产品自动取消策略。全机 Swap 事件不能全部归因给生成进程。
- 警告压力、Swap-out 增量、显著交互延迟即使未触发保护，也如实记录为问题；不会因完成图像而忽略。用户停止、系统分配失败和运行错误仍按原流程处理。

原 App/Pipeline 没有 GPU 吞吐强制中止逻辑；上一阶段中止来自外部实验脚本。本次不再使用该脚本，并移除 CLI 的显式 `--thermal-wait` 冷却等待选项；`--thermal-samples 1` 只诊断。原精度、算术顺序、分辨率、参考图 Token、六步调度与动态 LoRA 均不改变。

## 连续测试方法

`HardwareRuntimeStabilityTests` 通过 **实际 App GenerationEngine** 提交一个三图任务：同一进程、同一模型、同一参考图，Seed 42 → 43 → 42；同时加载 Turbo v0.3 r256、Qwen Fix v2、Canon DSLR、Samsung Photo，全部强度 1.0。参考图为首阶段保留的 1536×2304 输入，输出沿用完整质量基线的 **832×1248**（约 1.04 MP），不缩图减少负载。

直接读取既有生成 sidecar 的提示词、CFG、模式及输入内容哈希，随后仅追加三个适配器。输入由 Engine 复制到输出目录 `inputs/`；原图、所有参数、PNG/JSON、阶段事件、每步耗时、四点吞吐与失败信息均保留。三张之间没有进程重启、冷却或主动降低运行精度。第一张为条件冷缓存，后两张应命中无损 CPU Embedding 缓存；第一/三张相同 Seed 的完整输出必须逐像素一致。

释放断言包括每张 VAE 入口 MLX active <1 GiB、保存结果时 active <1 MiB，覆盖 DiT/LoRA、前缀 KV 和编译图跨阶段释放；结束记录 cache bytes，允许保留受限的 CPU 条件缓存。系统 footprint 回落与活跃数组分别记录，不能把已释放但由 OS 管理的映射页误算为模型对象仍存活。

响应性辅助指标为同一进程主 RunLoop 的 50 ms 心跳超时，以及每秒一次只记录耗时的 WindowServer 窗口列表查询。查询不截屏、不保存窗口标题或字典，不连接窗口共享。它们分别反映主线程调度与查询响应，**不等价于鼠标到屏幕的端到端延迟**；实际拖动、切换 App、输入顺畅度另外记录主人反馈。[Apple 文档](https://developer.apple.com/documentation/coregraphics/cgwindowlistcopywindowinfo(_:_:))说明该查询返回窗口信息且有成本，因此仅低频取样。

外部原生采样间隔 250 ms，记录目标 footprint、Mach timebase 换算后的 CPU 时间、进程 I/O 归属计数、全机压缩/Swap 和压力状态。原始 Swap 页乘本机实际页大小；GB 表格使用十进制。I/O 归属字节不等于物理 SSD 流量。critical 状态含义依据 [Apple 内存压力文档](https://developer.apple.com/documentation/dispatch/dispatch_memorypressure_critical)，具体 15 秒/128 MiB 保护线是本次实验选择。

```bash
swift test -c release --parallel --num-workers 2 --skip Hardware --xunit-output .tmp/unit.xml
LINGXI_RUN_STABILITY_TESTS=1 GATE_PASSES=2 \
  MLX_MAX_OPS_PER_BUFFER=100 MLX_MAX_MB_PER_BUFFER=200 MLX_ENABLE_TF32=0 \
  swift test -c release --filter HardwareRuntimeStabilityTests
```

真实测试需本机模型和首阶段保留的参考图记录；缺失时明确失败，不用合成图替代。全量外部资源采样与保护由本次 `/tmp` 原生助手提供，清理助手后，单独运行 XCTest 仍可复验 Engine、主线程心跳、像素和释放断言，但不自动重现外部压力保护。

## 实测结果

同一真实模型 XCTest 用例分别在 512 MiB 和 128 MiB 缓存预算下运行，各完成三张、每张完整六步，两轮均零失败。每轮仅开始前通过冷机校准，后续无冷却、无吞吐中止。最终采用 **128 MiB DiT 空闲缓存预算**；退出恢复原值，基础权重、适配器 dtype、KV 内容与算术顺序均不变。MLX 在异步回收时计数可暂时高于预算，不能把该值称作全部 GPU 分配的硬上限。

| 缓存预算 / 第几张 | Seed | 总秒数 | 稳态 2–6 秒/步 | 峰值 GB | 新增 Swap-out MiB | 本张运行探针最低 TFLOPS |
|---|---:|---:|---:|---:|---:|---:|

| 512 MiB / 1 | 42 | 82.573 | 8.775 | 23.553 | 1673.562 | 12.169 |
| 512 MiB / 2 | 43 | 76.234 | 9.012 | 23.909 | 252.562 | 12.637 |
| 512 MiB / 3 | 42 | 75.008 | 8.863 | 23.848 | 0.000 | 12.591 |
| 128 MiB / 1 | 42 | 81.231 | 8.862 | 23.441 | 0.000 | 12.111 |
| 128 MiB / 2 | 43 | 75.704 | 8.919 | 23.998 | 0.000 | 11.852 |
| 128 MiB / 3 | 42 | 76.617 | 9.029 | 23.961 | 0.000 | 11.042 |

以上为连续工作负载的实际耗时，**不是恒定冷机速度排名**。512 MiB 的三张运行内均有低于吞吐门限的点，仍继续并全部完成。128 MiB 最后一张末点达到 fair / 11.042 TFLOPS，也只标记温态，不中止。两轮均无 critical 内存压力，独立资源保护未触发。基础 Command Buffer 保持 100 ops / 200 MB。

| 连续三图期间 | 512 MiB | 128 MiB |
|---|---:|---:|
| 全机新增 Swap-out | 1,926.125 MiB | 0 MiB |
| 正常 / warning 压力累计 | 219.42 / 14.49 秒 | 233.69 / 0 秒 |
| 最长单次 warning | 4.33 秒 | 0 秒 |
| 主 RunLoop 延迟 P95 / 最大 | 3.34 / 4.73 ms | 3.33 / 16.79 ms |
| WindowServer 查询 P95 / 最大 | 3.15 / 47.72 ms | 2.08 / 17.83 ms |
| 目标进程 CPU 时间（采样区间） | 107.17 秒 | 106.89 秒 |
| 进程 I/O 归属读取 | 67.81 GB | 67.73 GB |
| 最后保存时 MLX active | 804 字节 | 48 字节 |
| Engine 完成时空闲缓存 | 0 字节 | 0 字节 |
| 完成约 5 秒后 footprint | 159.57 MB | 147.00 MB |

**主人在两轮期间实际拖动窗口、切换应用并输入文字，反馈“始终顺畅，未观察到明显卡顿”。** RunLoop 延迟为超过预定 50 ms 心跳间隔的部分，不是输入到显示延迟；WindowServer 查询也是独立代理指标，二者不替代该人工反馈。空闲主线程基线 P95 约 3.10 ms（512 MiB 轮），没有把系统固有定时误差全归因于生成。

512 MiB 轮新增 Swap-out 按最近阶段事件归属，主要出现在首张 Prefill/去噪及第二张去噪。128 MiB 三张均未出现新增 Swap-out，压力状态全程 normal；但两轮峰值 **23.909 vs 23.998 GB，没有峰值下降证据**。测试按 512→128 顺序进行，第一轮已经改变 OS 驻留与 Swap 状态，不能将第二轮零 Swap 全部归因于缓存预算，也不能保证任何后台负载下都零 Swap。直接可确认的变化是去噪阶段回调中空闲缓存从约 572–700 MiB 降至通常 128 MiB（个别回收时 286.7 MiB），相同工作负载仍完整生成且像素不变。

## 数值、质量与释放回归

三对对应 Seed 的 512/128 MiB 完整图像，ImageIO 解码后的尺寸、像素格式、行跨度和全部像素 SHA-256 均一致。两轮各自第一/第三张相同 Seed 42 也逐像素一致；首张条件 miss，后两张 hit。四 LoRA 参考图 Seed 42 的像素 SHA-256 为 `1e6915b7cd16d80ccac55547dead1f81912859da7d3d884417996ce9af12f927`。这验证缓存预算调整及连续条件复用没有改变输出，不把四 LoRA 与单 Turbo 的风格、姿态差异当作优化误差。

每张均通过 DiT/LoRA/KV/编译图在 VAE 入口前释放的 active <1 GiB 断言；保存时 0–804 字节、结束缓存 0，随后进程 footprint 回落到约 147–160 MB。CPU 条件缓存保留且受既有 128 MiB 上限约束。最终公共回归 20 项零失败；两个配置各执行同一个完整稳定性用例一次，共六张完整输出。未将默认跳过的其他真实模型用例计作本轮通过。

首次追加的纯文生图 1024² / 单 Turbo / 六步回归，像素仍与既有基线一致：`d3c4a24a92e61cd523d03ea87afd493083078d6de2947b652e7a0902b25750ef`。该轮开始前两次 nominal 校准通过，运行中吞吐低于门限，仅作为吞吐校验不足的完整回归记录，不冒充冷机基准；其命令、六步记录及失败的性能有效性判断保留于 `pure-128/`。

随后在无外部资源/窗口查询采样的条件下，等待连续五次 nominal 且达到吞吐门限（相隔 30 秒，本次总等待 230 秒；90 秒处失败探针也保留），追加完整纯文生图回归。稳态 **6.022788 秒/步**、总耗时 **48.383 秒**，四点吞吐为 **12.529 / 12.203 / 12.861 / 11.133 TFLOPS**，结束 nominal / 13.01。四点性能有效性判定为 **未全部通过**；像素仍与历史单 Turbo 基线完全相同。运行内探针与独立校准时的资源驻留及缓存预算不同，吞吐下降可能受分配/资源竞争影响，不能据此断言 GPU MHz 降频。这个结果接近 6 秒，但不写成恒定冷机、严格 ≤6.000 的证明，也不为缩短 0.023 秒改变精度或生成质量。原始记录为 `pure-final/` 和 `pure-final-gate.log`。

两轮复杂负载实际布局均为 embedding 1,038、image slots 1,014、前缀 4,080、target 4,056，32 层前缀 KV 合计 2,139,095,040 字节；各日志中三张均一致，参考图 Token 没有减少。
